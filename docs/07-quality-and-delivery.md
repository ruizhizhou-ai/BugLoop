# BugLoop 质量与交付

> 本文件的核心职责：定义验收标准、交付物、非功能要求、关键用例、实施顺序、一期边界和待确认事项。章节编号沿用 `BugLoop_SPEC_v1.0` 原编号，便于追溯。

## 三十一、一期验收标准

达到以下条件即可认为一期项目完成：

1. 用户能够创建并进入工作空间；
2. 用户能够在自己加入的多个工作空间之间切换；
3. 工作空间管理员能够管理成员和成员角色；
4. 不同工作空间之间的 Bug 数据能够正确隔离；
5. Bug 负责人和验收人只能从当前工作空间成员中选择；
6. 用户能够提交 Bug；
7. 支持 Markdown 详细说明；
8. Markdown 可以编辑和预览；
9. 文档修改可以查看历史版本；
10. 支持截图附件；
11. 支持人员指派；
12. 支持优先级；
13. Bug 可以正常进行状态流转；
14. 开发人员可以填写修复说明；
15. 可以提交验收；
16. 验收可以通过或者拒绝；
17. 验收失败可以重新处理；
18. 支持评论；
19. 关键操作自动生成日志；
20. 权限控制符合设计；
21. 系统能够成功部署到内部服务器；
22. 可以完整跑通一条：

```Plain
提交
→ 指派
→ 修复
→ 验收
→ 关闭
```

流程。

## 五十四、非功能性要求

### 54.1 数据隔离

所有 Bug 查询必须带 Workspace 边界。

禁止只根据：

```Plain
bugId
```

查询后直接返回数据。

查询详情后仍然必须验证当前用户是否属于对应 Workspace。

### 54.2 性能

第一期不针对超大规模设计，但必须满足：

- 所有列表分页；
- 常用查询字段建立索引；
- 禁止明显 N+1 查询；
- 文件采用流式下载，不一次性全部读入内存。

### 54.3 安全

必须实现：

- 登录鉴权；
- 后端权限校验；
- 密码哈希；
- SQL 注入防护；
- Markdown XSS 防护；
- 文件类型和大小校验；
- 文件路径穿越防护；
- 接口异常不返回堆栈。

### 54.4 日志

服务端使用：

```Plain
SLF4J
```

禁止正式代码使用：

```Plain
System.out.println
```

不得输出：

```Plain
密码
JWT Token
敏感认证信息
```

### 54.5 数据备份

正式部署后至少考虑：

```Plain
MySQL 定期备份
附件目录定期备份
```

第一期无需开发可视化备份页面。

## 五十五、关键验收测试用例

| 编号 | 测试内容 | 预期结果 |
|---|---|---|
| AC-WS-01 | 用户创建工作空间 | 创建成功且自动成为 OWNER |
| AC-WS-02 | MEMBER 尝试管理成员 | 返回 403 |
| AC-WS-03 | 跨工作空间访问 Bug | 返回 403 / 404，不泄露数据 |
| AC-WS-04 | 删除最后一个 OWNER | 操作失败 |
| AC-BUG-01 | 创建 Bug 不指定负责人 | 创建成功，状态 TODO |
| AC-BUG-02 | 指派非 Workspace 成员 | 操作失败 |
| AC-BUG-03 | 非负责人点击开始处理 | 返回 403 |
| AC-BUG-04 | TODO 直接关闭 | 返回 409 |
| AC-BUG-05 | PROCESSING 未填写修复说明提交验收 | 操作失败 |
| AC-BUG-06 | 负责人提交验收 | 状态变 WAIT_ACCEPTANCE |
| AC-BUG-07 | 非验收人验收 | 返回 403 |
| AC-BUG-08 | 验收通过 | 状态 CLOSED，并生成验收和日志记录 |
| AC-BUG-09 | 验收驳回未填写原因 | 操作失败 |
| AC-BUG-10 | 验收驳回 | 状态 REOPENED，reopen_count + 1 |
| AC-MD-01 | 修改 Markdown 描述 | 保存旧版本并生成操作日志 |
| AC-MD-02 | Markdown 内容未变化 | 不产生新历史版本 |
| AC-FILE-01 | 上传合法图片 | 上传并可预览 / 下载 |
| AC-FILE-02 | 上传可执行文件 | 拒绝上传 |
| AC-LOG-01 | 状态变化 | 自动写日志 |
| AC-CON-01 | 两用户同时修改同一 Bug | 后提交的旧 version 请求返回 409 |

以上测试必须通过后才能认为一期核心业务闭环完成。

## 五十七、Codex 开发输入要求

开发时 Codex 应至少读取：

```Plain
BugLoop_SPEC_v1.0.md 索引及本次任务涉及的 Spec 文档
AGENTS.md
现有项目目录
数据库 Migration
```

每次开发任务遵循：

```Plain
1. 阅读 Spec

4. 只修改本次需求涉及模块
```

- 引入微服务；

- 新增 Redis；

## 五十九、待业务确认项

以下内容已经给出一期默认值，但在正式开发前可以再次和需求方确认：

1. 所有 Workspace 成员是否都能查看 Workspace 全部 Bug；
2. Bug 创建人是否一定拥有最终验收权，还是由创建时单独选择验收人；
3. CLOSED Bug 是否允许继续评论；
4. OWNER / ADMIN 是否需要特殊“强制关闭”能力；
5. 工作空间是否允许所有用户自行创建；
6. 单附件 20MB、单 Bug 20 个附件是否满足公司实际使用；
7. 是否已有公司统一登录 / SSO。

如果没有新的业务要求：

> 按本 Spec 文档集的默认规则实现。
