# BugLoop 前端页面 Spec

> 本文件的核心职责：定义一期页面结构、交互行为以及不同 Bug 状态下允许展示的操作。章节编号沿用 `BugLoop_SPEC_v1.0` 原编号，便于追溯。

## 五十二、前端页面 Spec

### 52.1 登录页

字段：

```Plain
用户名
密码
```

成功登录后：

- 如果只有一个工作空间，直接进入；
- 如果有多个工作空间，进入最近使用工作空间；
- 如果没有工作空间，进入“创建 / 加入工作空间”的空状态页。

### 52.2 顶部工作空间切换

页面顶部始终显示当前 Workspace。

点击后显示：

```Plain
当前用户加入的工作空间
+
创建工作空间
```

切换 Workspace 后：

- Bug 列表刷新；
- 我的 Bug 刷新；
- 成员列表刷新；
- URL 或前端 Store 中更新 workspaceId。

### 52.3 首页

一期首页保持简单。

显示：

```Plain
我的待处理
我的处理中
待我验收
最近更新Bug
```

不建设复杂 BI Dashboard。

### 52.4 Bug 列表

表格列：

```Plain
Bug编号
标题
优先级
状态
负责人
提交人
验收人
创建时间
更新时间
```

筛选：

```Plain
关键字
状态
优先级
负责人
提交人
时间范围
```

默认：

```Plain
20条 / 页
updatedAt DESC
```

### 52.5 创建 Bug 页面

字段顺序建议：

```Plain
标题 *
详细说明 Markdown *
优先级
负责人
验收人
附件
```

默认：

```Plain
priority = P2
acceptor = currentUser
```

### 52.6 Bug 详情页

页面结构：

```Plain
顶部：
BUG编号 / 标题 / 状态 / 优先级 / 负责人 / 验收人

主体：
问题描述
附件
修复说明
验收记录
评论
操作日志
文档历史
```

顶部根据状态显示业务按钮。

#### TODO

当前负责人看到：

```Plain
开始处理
```

OWNER / ADMIN 看到：

```Plain
指派
修改验收人
```

#### PROCESSING

当前负责人看到：

```Plain
编辑修复说明
提交验收
```

#### WAIT_ACCEPTANCE

当前验收人看到：

```Plain
验收通过
验收驳回
```

#### REOPENED

当前负责人看到：

```Plain
开始处理
```

#### CLOSED

不显示任何状态操作按钮。

只保留查看、评论。

### 52.7 成员管理

OWNER / ADMIN 可操作：

```Plain
添加成员
移除成员
调整角色
```

普通 MEMBER：

> 只读成员列表。

### 52.8 工作空间设置

OWNER 可以：

```Plain
修改名称
修改说明
停用工作空间
```

ADMIN：

```Plain
可以修改名称和说明
不能停用
```
